# Проверка на телефоне в вашей Wi-Fi сети

Цель шага 1.4: открыть MedSync с телефона и получить запрос на доступ к микрофону. Телефон открывает микрофон только на защищённом соединении (HTTPS), поэтому нужен свой сертификат. Всё работает только в вашей домашней или офисной сети; в интернет ничего не выходит.

## Что делает компьютер

Команда `npm run dev:lan`:
1. находит адрес компьютера в сети (например, `192.168.0.127`);
2. один раз создаёт корневой сертификат и сертификат сайта в папке `C:\Users\<вы>\medsync-dev-certs` — **вне проекта и вне OneDrive**, чтобы закрытый ключ никуда не синхронизировался и не попал в Git;
3. запускает сервер и сайт по HTTPS на этом адресе.

Корневой сертификат ограничен частными сетями и `localhost`: даже если его ключ украдут, им нельзя подписать сертификат для настоящего сайта в интернете. Проверено: сертификат для публичного имени отклоняется.

Если адрес компьютера изменился (роутер выдал другой), просто запустите команду снова: выпустится новый сертификат сайта, а корневой на телефоне остаётся прежним.

## Запуск

1. Закройте уже запущенный сервер, если он есть (порт 8787), и сайт на порту 5173.
2. В папке проекта:
   ```powershell
   npm run dev:lan
   ```
3. Windows может спросить доступ к сети. Разрешите только для **частной сети**.

## Установка сертификата на телефон (один раз)

Нужен только файл `rootCA.crt` (это открытый сертификат, его можно отправить себе по почте или в мессенджере). Файлы `*.key` с компьютера никуда не отправляйте.

**iPhone**
1. Откройте `rootCA.crt` на телефоне (из почты или «Файлов») → «Разрешить» → профиль загружен.
2. Настройки → «Профиль загружен» → «Установить».
3. Настройки → Основные → Об этом устройстве → Доверие сертификатов → включите **MedSync local dev CA**.

**Android**
1. Настройки → Безопасность (или «Безопасность и конфиденциальность») → Другие настройки безопасности → Шифрование и учётные данные → Установить сертификат → **Сертификат ЦС** → подтвердите предупреждение → выберите `rootCA.crt`.
2. Chrome доверяет такому сертификату. Приложения (в Этапе 4) без отдельной настройки — нет.

После проверки лучше удалить сертификат с телефона (там же, где устанавливали).

## Проверка

1. Телефон в той же Wi-Fi сети, что и компьютер.
2. В браузере телефона откройте адрес, который напечатала команда (`https://192.168.…:5173`). Замка и предупреждений быть не должно.
3. Войдите вымышленным пользователем из `data/demo-credentials.txt` и откройте «Приём» → «Живая запись»: телефон спросит доступ к микрофону.

## Установка на главный экран (шаг 1.5)

Установка работает только из собранной версии. Запустите вместо обычной команды:

```powershell
npm run dev:lan:app
```

Она сама соберёт приложение и запустит его по HTTPS на том же адресе. Затем на телефоне:
- **Android (Chrome):** меню ⋮ → «Установить приложение» (или «Добавить на главный экран»).
- **iPhone (Safari):** «Поделиться» → «На экран «Домой»».

Откройте значок MedSync на главном экране: приложение запустится без адресной строки. Если связи нет, показывается страница «Нет связи с сервером». Данные пациентов, ответы сервера и код в кэше телефона не сохраняются.

## Осторожно

- Пока команда запущена, к сайту может обратиться любой в вашей Wi-Fi сети. Данные защищены входом с кодом, но используйте только доверенную сеть, не общественную. Остановите команду (Ctrl+C), когда закончили.
- Только вымышленные данные, как и везде в демо.
- Распознавание речи (`ASR_URL`) работает на компьютере; телефон ходит к нему через сервер MedSync.
