# Приложение Android (шаг 4.1)

> **Приостановлено 2026-11-28:** цель проекта теперь — веб-приложение для ноутбуков. Эта работа сохранена на потом и не проверялась на телефоне; текущий план — `docs/DEVELOPMENT_PLAN.md`.

Тот же код, что и сайт, упакован в приложение с помощью Capacitor 8 (`capacitor.config.ts`, папка `android/`). Только вымышленные данные.

## 1. Как приложение работает с сервером

- Страница приложения открывается **с самого телефона** (`https://localhost` внутри приложения). Код и файлы лежат в установленном приложении, а данные — только на сервере.
- Адрес сервера вшивается при сборке (`VITE_API_BASE`) и добавляется в политику безопасности страницы (CSP `connect-src`).
- Вход — по токенам (`client: "app"`): короткий access-токен на 5 минут и одноразовый refresh-токен (шаг 1.2). Cookie приложение не использует. **Пока токены хранятся только в памяти:** после закрытия приложения нужно войти снова. Безопасное хранение (Keystore) и блокировка приложения — шаг 4.2.
- Сервер разрешает приложению запросы только с `https://localhost` и `capacitor://localhost` (`APP_ORIGINS`); `npm run dev:lan` задаёт это сам.

## 2. Что настроено в проекте Android

| Что | Где |
|---|---|
| Только https, без открытого текста | `AndroidManifest.xml` (`usesCleartextTraffic=false`), `res/xml/network_security_config.xml` |
| Рабочая сборка доверяет только системным корневым сертификатам | `src/main/res/xml/network_security_config.xml` |
| Отладочная сборка дополнительно доверяет локальному сертификату разработки (ограничен частными адресами) | `src/debug/res/xml/network_security_config.xml`; файл сертификата копирует `scripts/android.ts`, в Git он не попадает |
| Ничего не попадает в резервные копии Android и перенос на другой телефон | `allowBackup=false`, `res/xml/data_extraction_rules.xml` |
| Разрешения: только интернет и микрофон | `AndroidManifest.xml` |
| Отладка страницы через Chrome выключена в рабочей сборке | `capacitor.config.ts` |

## 3. Инструменты на компьютере (один раз)

Установлены без прав администратора в `C:\Users\User\android-dev` (вне OneDrive):

- `jdk-21.0.13.1+2` — Microsoft Build of OpenJDK 21 (проверена контрольная сумма SHA-256 с сайта Microsoft);
- `sdk` — Android command-line tools (проверена SHA-1 из каталога Google), platform-tools, платформа Android 36, build-tools 36.0.0. Лицензия Android SDK принята владельцем 2026-11-28.

Gradle и библиотеки сборки скачиваются при первой сборке в `C:\Users\User\.gradle`.

## 4. Сборка и установка на телефон

1. На компьютере один раз: `npm run db:setup` (ключ шифрования), `npm run seed` (вымышленные пользователи, если ещё нет).
2. Запустить сервер для телефона: `npm run dev:lan` (печатает адрес вида `https://192.168.1.5:5173`). Телефон — в той же Wi-Fi сети.
3. На телефоне: Настройки → О телефоне → семь раз нажать «Номер сборки» → «Для разработчиков» → включить «Отладка по USB». Подключить кабелем, на телефоне разрешить отладку для этого компьютера.
4. На компьютере:

```powershell
npm run android -- --install
```

Скрипт соберёт приложение с адресом сервера этого компьютера, соберёт отладочный APK (`android/app/build/outputs/apk/debug/app-debug.apk`) и установит его. Другой адрес сервера: `npm run android -- --api https://адрес:5173 --install`.

5. Открыть MedSync на телефоне, войти (данные из `data/demo-credentials.txt`), разрешить микрофон, когда приложение спросит.

## 5. Что проверить на телефоне (критерий шага 4.1 — «приложение работает на телефоне Android»)

- [ ] Приложение открывается, показывает экран входа.
- [ ] Вход с паролем и кодом работает; через 5 минут бездействия запросы продолжают работать (токен обновляется сам).
- [ ] Пациенты и история открываются; демо-приём проходит до подписи.
- [ ] Живая запись: запрос разрешения на микрофон, распознавание (если запущен сервис распознавания, `ASR_URL`).
- [ ] Без Wi-Fi приложение показывает ошибку связи, а не падает.
- [ ] Выход работает; после закрытия приложения нужно войти снова (ожидаемо до шага 4.2).
