# MedSync

AI-скрайб для клиник Кыргызстана: слушает разговор врача с пациентом, расшифровывает его, достаёт ключевые факты и готовит черновик медицинского документа. Врач проверяет черновик, правит, подписывает и отправляет в медкарту.

> **Это демо.** Все пациенты и данные вымышленные. Разговор — заранее написанный сценарий, а не запись и не реальное распознавание речи. ЭЦП и отправка в медкарту — имитация без юридической силы. Реальной интеграции с Түндүк нет.

## Запуск

```powershell
npm install
npm run dev      # http://localhost:5173
npm run build    # проверка типов + сборка
npm test         # проверка ПИН и разбора ответа модели
npm run server   # API для «Составить документ» (нужен ключ, см. ниже)
```

**Составление документа моделью (эксперимент).** Скопируйте `.env.example` в `.env`, впишите `ANTHROPIC_API_KEY`, запустите `npm run server` рядом с `npm run dev`. На странице «Живая запись» после расшифровки появится кнопка «Составить документ»: расшифровка уходит модели Claude через локальный сервер (ключ в браузер не попадает), а ответ проверяется — номера реплик, которых нет в разговоре, отбрасываются, а факты без источника подсвечиваются жёлтым. Только вымышленные данные: реальные данные пациентов отправлять внешней модели нельзя.

Стек: Vite, React, TypeScript, Tailwind CSS 4.

## Что есть

- **Приём** — выбор типа документа (Осмотр, Больничный лист, Направление, Справка), «разговор» появляется по таймеру, документ заполняется по мере реплик.
- **Источники фактов** — у каждого утверждения в документе есть номера реплик (`#N`); при наведении реплика подсвечивается. Утверждение без источника выделяется жёлтым с кнопками «Оставить / Убрать / Исправить».
- **Журнал изменений** — каждое действие врача записывается с временем.
- **Проверка аллергий** — если врач назначил препарат из группы, на которую у пациента аллергия, подписать документ нельзя, пока врач не уберёт назначение или не подтвердит его.
- **Подпись и отправка** — демо-ЭЦП (SHA-256 от текста документа) и имитация отправки в медкарту; печать / PDF через браузер.
- **Пациенты** — список с ПИН (14 цифр).
- **История** — подписанные документы, хранятся в `localStorage` браузера.

## Структура

```
src/data/script.ts    реплики разговора и документы по типам (с sourceIds)
src/data/patients.ts  вымышленные пациенты и аллергии
src/data/pin.ts       генерация и проверка ПИН
src/data/allergy.ts   демо-справочник групп препаратов
src/data/history.ts   хранилище истории (localStorage)
src/pages/            Home, Patients, Appointment, History
```

## Важные допущения

- **ПИН:** 14 цифр = пол + дата рождения `ДДММГГГГ` + 5 цифр порядкового номера. Кодировку пола (1 — женщина, 2 — мужчина) нужно сверить с официальной спецификацией.
- **Аллергии:** справочник в `allergy.ts` — упрощённый, не медицинский. Для реального использования нужна фармакологическая база.
- Нельзя заявлять соответствие HIPAA/GDPR; для формулировок о персональных данных нужен юрист и закон Кыргызстана о персональной информации.
- Реальные данные пациентов в репозиторий добавлять нельзя.
